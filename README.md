# КБЖУ-бот для Telegram — учёт питания по фото

Telegram-бот для совместного учёта питания в групповом чате с темами. Кидаешь фото тарелки на кухонных весах — бот распознаёт блюдо, читает вес с дисплея, считает КБЖУ и записывает в Google-таблицу. Полностью бесплатный стек: Google Apps Script (хостинг) + Gemini API (распознавание) + Google Sheets (база).

## Возможности

- 📸 **Фото тарелки на весах** — определяет блюдо и вес с дисплея одним снимком
- 📸 **Фото этикетки** — читает таблицу КБЖУ и массу нетто с упаковки
- ✍️ **Текст в свободной форме** — «гречка 200 г», «2 тоста, слайс сыра, 6 черри»; «не знаю, прикинь» — оценит типичную порцию с пометкой «примерно»
- ❓ **Уточняющие вопросы с памятью** — если не хватает данных, задаёт один вопрос; ответ «300» связывается с исходным фото (кэш 30 минут)
- ⏪ **Внесение задним числом** — `/вчера гречка 200 г` (или фото с такой подписью) записывает во вчерашний день и пересчитывает вчерашнюю сводку
- ↩️ **Перенос записи** — ответ «вчера» на запись бота (или на своё сообщение с едой) переносит её из сегодня во вчера и пересчитывает оба дня; задвоение исключено по построению
- 👥 **Несколько пользователей** — различает участников, у каждого свой учёт и своя норма; переносить чужие записи нельзя
- 🎯 **Норма КБЖУ** — вручную (`/норма 1600`) или расчёт по мини-анкете (формула Миффлина—Сан-Жеора, активность 1.3/1.45/1.6, мягкий дефицит 15%)
- 🌙 **Ночная сводка** — только цифры по каждому участнику, без комментариев и оценок
- 📅 **Недельный блок** — раз в неделю к ночной сводке добавляются средние за 7 дней и короткий комментарий от ИИ по строгим бережным правилам (см. «Философия комментариев»)
- 🎲 **Детерминизм** — `temperature: 0` и дефолты для неоднозначных описаний: одинаковый вход всегда даёт одинаковую оценку
- 🛡 **Надёжность** — защита от повторной доставки Telegram (dedup по `update_id`), повтор отправки при сбоях Telegram (5xx/429, до 3 попыток), фолбэк на лёгкую модель при лимитах Gemini, лог ошибок в лист Debug

## Философия комментариев

Ежедневная сводка молчит — только цифры: комментарий к каждому дню неизбежно драматизирует шум, а выводы честны только на недельных средних. Недельный комментарий пишется по жёстким правилам, безопасным в том числе для людей с непростыми отношениями с едой:

- советы только в форме «что добавить», никогда «что убрать/сократить»;
- похвала только за достаточность и стабильность, никогда за «меньше съедено»;
- запрещены идеи компенсации («выровнять», «отработать») и морализация еды («срыв», «вредное», «правильное»);
- тело, вес и фигура не упоминаются вообще;
- при менее чем 4 днях с записями — комментария нет.

## Структура Google-таблицы

Создай таблицу с двумя листами.

**Лист «Лог»** — заголовки в первой строке:

| A Дата | B Время | C Кто | D Блюдо | E Вес, г | F Ккал | G Белки | H Жиры | I Углеводы | J msg_id | K src_msg_id |
|---|---|---|---|---|---|---|---|---|---|---|

Колонки J и K — технические: связки записей с сообщениями Telegram (ответ бота и исходное сообщение пользователя), на них держится механика переноса «вчера». Даты и время бот пишет **текстом** (с ведущим апострофом) — это защита от тихой конвертации в даты и связанных с часовыми поясами багов подсчёта.

**Лист «Настройки»**:

| user_id | Имя | Норма ккал | Норма Б | Норма Ж | Норма У |
|---|---|---|---|---|---|

Лист «Debug» бот создаст сам — туда пишутся ошибки.

## Установка

### 1. Google-таблица

Создай таблицу по структуре выше. Из адресной строки скопируй **ID таблицы** — строку между `/d/` и `/edit`. Проверь часовой пояс: **Файл → Настройки → Часовой пояс** — поставь свой (тот же, что впишешь в константу `TZ`).

### 2. Бот в BotFather

1. Найди **@BotFather** (с галочкой верификации) → `/newbot` → имя → уникальный username на `bot`. Сохрани **токен**.
2. **Обязательно:** `/setprivacy` → выбери бота → **Disable** (иначе бот в группе не видит обычные сообщения и фото).
3. `/setjoingroups` → **Enable**.
4. Для меню команд: `/setcommands` → отправь:
   ```
   day - Сводка за сегодня
   week - Итоги за 7 дней
   yesterday - Внести еду во вчерашний день
   del - Удалить последнюю запись
   norm - Норма: задать или рассчитать
   cancel - Сбросить вопрос/анкету
   help - Шпаргалка
   ```
   (Telegram подсказывает только латинские команды; русские алиасы работают параллельно.)

### 3. Ключ Gemini

1. [aistudio.google.com](https://aistudio.google.com) → **Get API key** → **Create API key**. Карта не нужна.
2. Если AI Studio не может сам создать проект — создай его руками в [console.cloud.google.com](https://console.cloud.google.com) (прими Terms → New project), затем в AI Studio: Create API key → Import project.

⚠️ Известная проблема: `403 PERMISSION_DENIED: Your project has been denied access` встречается даже на свежих аккаунтах — Google флагует проекты внутренним фильтром. Быстрое решение — создать ключ с другого Google-аккаунта (боту нужен один ключ, неважно чей).

⚠️ Вторая: `404 model is no longer available to new users` — новым ключам доступны не все имена моделей. В коде используются «плавающие» `gemini-flash-latest` / `gemini-flash-lite-latest`, они работают всегда; актуальный список моделей своего ключа можно получить запросом `GET /v1beta/models?key=...`.

### 4. Скрипт

1. Открой таблицу → **Расширения → Apps Script**. Ошибка «Не удалось открыть файл» = конфликт нескольких Google-аккаунтов в браузере; открой таблицу в инкогнито под одним аккаунтом.
2. Вставь содержимое `Code.gs`, заполни блок НАСТРОЙКИ (`TOPIC_ID` и `CHAT_ID` узнаешь в шаге 6). Сохрани.

### 5. Публикация и вебхук

1. **Начать развёртывание → Новое развёртывание** → **Веб-приложение**: запуск **От моего имени**, доступ **Все** (стучится сервер Telegram; адрес — длинная случайная строка).
2. Разреши доступы («непроверенное приложение» — это твой же скрипт: Advanced → Перейти → Разрешить).
3. Скопируй URL (`.../exec`) и открой в браузере ссылку:
   ```
   https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=<URL_СКРИПТА>
   ```
   Ответ должен быть `{"ok":true,...,"description":"Webhook was set"}`. Не потеряй `?` между `setWebhook` и `url=`.

### 6. Узнаём TOPIC_ID, CHAT_ID и user_id

1. Временно добавь в начало `doPost` (после `const update = ...`):
   ```javascript
   debugLog('Пришло: ' + e.postData.contents.slice(0, 300));
   ```
2. Обнови версию (см. «Важно про обновления»), добавь бота в чат и сделай **администратором**.
3. Напиши что-нибудь в нужной теме → в листе Debug появится сырое сообщение: `"message_thread_id"` → TOPIC_ID, `"chat":{"id":-100...}` → CHAT_ID, `"from":{"id":...}` → user_id для «Настроек».
4. Впиши значения, удали временную строку, обнови версию.

### 7. Ночная сводка

1. Запусти вручную функцию **setupTrigger** (один раз; разреши доступ к триггерам).
2. Час запуска (`atHour(0)` = полночь) считается по часовому поясу **проекта**: ⚙️ Настройки проекта → Часовой пояс. Триггер стреляет не минута в минуту, а в окне ~час.
3. В `dailySummary` точка отсчёта сдвинута на 3 часа назад — сводка всегда подводит итоги **закончившегося** дня, даже если триггер проснулся после местной полуночи. Это важно, когда пояс триггера и пояс записей (`TZ`) различаются.
4. Предпросмотр недельного блока без ожидания: запусти **testWeekly** (пришлёт в чат!).

### ⚠️ Важно про обновления кода

После **любого** изменения кода Telegram говорит со старой версией, пока не сделать:
**Начать развёртывание → Управление развёртываниями → ✏️ → Версия: «Новая версия» → Начать развёртывание.**
URL не меняется, вебхук перенастраивать не нужно. «Новое развёртывание» вместо обновления создаёт второй URL — и вебхук смотрит в пустоту.

Если изменения затронули новые права (таблица, триггеры) — запусти любую функцию вручную и раздай разрешения, иначе вебхук будет молча падать: он не умеет спрашивать доступы.

## Команды

| Команда | Что делает |
|---|---|
| *(просто еда: фото/текст)* | распознать и записать в сегодня |
| `/вчера <еда>` (`/yesterday`) | записать во вчерашний день + пересчёт вчерашней сводки |
| *реплай «вчера» на запись бота или своё сообщение с едой* | перенести запись из сегодня во вчера + пересчёт обоих дней |
| `/день` (`/day`) | сводка за сегодня по всем |
| `/неделя` (`/week`) | итоги за 7 дней |
| `/удали` (`/del`) | удалить свою последнюю запись |
| `/норма 1600` (`/norm`) | норма вручную; с БЖУ: `/норма 1600 120 50 150` |
| `/норма расчёт` | расчёт по анкете |
| `/отмена` (`/cancel`) | сбросить вопрос бота или анкету |
| `/помощь` (`/help`) | шпаргалка |

## Траблшутинг

| Симптом | Причина и решение |
|---|---|
| Бот молчит совсем | `getWebhookInfo`: совпадает ли `url` с активным развёртыванием? Нет ли двух развёртываний? |
| Молчит, в «Выполнениях» doPost «завершено» | Неверный `TOPIC_ID`, или скрипту не хватает разрешений — запусти любую функцию вручную и раздай доступы |
| «Выполнения» есть, Debug пуст | Скрипт падает до первой записи (обычно права на таблицу) — ручной запуск покажет ошибку |
| `403 Your project has been denied access` | Флаг Google на аккаунте — ключ с другого аккаунта |
| `404 model is no longer available` | Используй «плавающие» имена моделей (уже в коде) |
| `429 quota` / `503 high demand` от Gemini | Норма для free tier в пиковые часы — фолбэк на лёгкую модель уже в коде, в Debug останется след «Ответила запасная модель» |
| Сводка не пришла | Проверь по цепочке: ⏰ Триггеры (жив ли dailySummary и когда последний запуск) → Выполнения (статус) → Debug. `Telegram отказал: 502` = сбой на стороне Telegram; в коде стоит повтор отправки до 3 раз |
| Сводка приходит не ровно в назначенный час | Норма: окно запуска триггеров ~1 час, по поясу проекта |
| Бот обработал сообщение дважды | Telegram ретраит медленные ответы — dedup по `update_id` уже в коде |
| Сумма дня 0 или равна последней еде | Рассинхрон часовых поясов таблицы и скрипта — в коде уже починено (даты текстом), но проверь пояс таблицы |
| Одинаковая еда — разные калории | В коде уже `temperature: 0` + дефолты; остаточные ±2 ккал — округление. Разброс остался — смотри Debug, не отвечает ли запасная модель |

## Безопасность

- **Никогда не коммить реальные токены** — в репозитории только плейсхолдеры.
- Токен засветился → BotFather `/revoke` → новый токен в скрипт → новая версия → заново `setWebhook`. Ключ Gemini пересоздаётся в AI Studio.
- На бесплатном тире Gemini запросы могут использоваться Google для обучения моделей.

## Точность

КБЖУ по фото — оценка: этикетки и простые продукты ±10%, составные блюда до ±30%. `temperature: 0` даёт повторяемость, но не абсолютную точность. Рабочая стратегия: стабильные оценки + сверка недельных средних с реальной динамикой раз в 2–3 недели и корректировка нормы через `/норма`. Систематические ошибки этот контур ловит скопом. Бот — инструмент учёта, не замена консультации специалиста.
